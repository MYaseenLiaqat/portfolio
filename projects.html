CASE 01 · APPLIED AI / RESEARCHFlagship

AI Learning Research

Problem. Build an experimental learning platform where AI can support a learner without silently becoming the learner, while keeping conditions reproducible enough for research.

01

Freeze experimental provenance. Learner condition, prompt version, model/provider identifiers, module version, and AI cap are persisted so mutable runtime settings do not rewrite the study history.

02

Control assistance. AI access is condition-aware, attempts are ownership-checked, supported sessions expire, and interaction count is capped at eight.

03

Grade deterministically. Code runs in a fresh namespace with an explicit result variable, while automated tests cover access, submission, scheduling, and prompt integrity.

5 study phases8 AI turns max20m supported phase15+ integrity tests

Designed around reproducibility and controlled assistance, not just chatbot functionality.

CASE 02 · FULL-STACK AILive ↗

Reflct

Problem. Put journaling, habits, goals, and an AI companion into one product without treating the AI layer as a disconnected demo.

01

Keep product state central. Supabase provides the persistent application data that the experience is built around.

02

Add retrieval before inference. LlamaIndex is used as the retrieval layer so the AI experience can work from relevant application context instead of a context-free prompt.

03

Ship the full loop. Next.js handles the user-facing product while Groq provides the inference layer behind the AI companion.

CASE 03 · PRODUCTION BACKENDLive ↗

Mabros Couriers

Problem. Provide a dependable backend for a local courier operation where orders, deliveries, tracking, and service integration all need to move through one API surface.

01

Centralize operational workflows. The Flask API is the application boundary for order, delivery, and tracking operations.

02

Keep data integration practical. Firebase supports the backend data needs without introducing infrastructure beyond the scale of the client.

03

Standardize deployment. Docker packages the backend so local development and production delivery use the same service boundary.
